# 交换机端口管理工具 · 使用说明

交换机端口资源管理：**登录交换机 → 采集 → 分析终端接入位置 / 端口使用情况 / 可疑端口 → 输出 Excel**，支持命令行与 Web 界面两种用法。

---

## 1. 目录结构

```
交换机端口管理工具\
├── net_port_tool\              核心代码包（不要单独移动其中的文件）
│   ├── config.py               路径与设备清单加载

│   ├── webapp.py               FastAPI Web 服务
```

## 2. 输入文件格式

### switch_table.xlsx（交换机清单）
| 设备名称 | IP地址 | 用户名 | 密码 | 是否需要检查 | 是否核心交换机 |
| --- | --- | --- | --- | --- | --- |
| CORE-SW | 172.17.115.254 | admin | ****** | 是 | 是 |
| EBG-1FJ01-SA-SWITCH-02 | 172.17.115.80 | admin | ****** | 否 | 否 |

- `设备名称 / IP地址` 必需，其余可缺；列名支持常见别名（如 IP / 管理IP / 账号 / 口令 等）。
- `是否核心交换机` 填 `是/yes/true/1` 即视为核心；未填则按“无核心”弱模式运行（连线/终端定位会受限）。
- 凭据只从这个表格读，代码里不再写死密码。

### 终端IP表.xlsx（终端清单）
| 设备名称 | IP地址 |
| --- | --- |
| 前台-PC | 10.20.30.41 |

- 只有 `IP地址` 是必需列。终端定位靠“核心 ARP 的 IP→MAC + 各交换机 MAC 表反查”。

## 3. 用法一：Web 界面（推荐）

```powershell
cd d:\pythonProject3\交换机端口管理工具
& "d:\pythonProject3\venv\Scripts\python.exe" -m net_port_tool.webapp
```

浏览器打开 **http://127.0.0.1:8000** ，页面上可以：

1. **选择/上传设备清单**：直接填路径，或点“上传”按钮传 Excel。
2. **勾选功能模块**：命名验证 / 交换机连线 / 终端定位接入表 / 端口使用表 / 可疑端口清单。
3. **设置并发**（默认 6，可 1~32）与是否“自动发现未知交换机”。
4. 点「开始采集分析」，右侧实时显示 **进度条 + 滚动日志**。
5. 完成后：**结果预览**支持按 Sheet 分页查看，点「下载 Excel」导出。
6. 每次运行都会存到 `net_port_tool_runs\<任务号>\`，**历史任务**面板可随时回看与下载（重启服务后仍在）。

> 想换端口：`uvicorn net_port_tool.webapp:app --host 0.0.0.0 --port 8080`

## 4. 用法二：命令行

```powershell
cd d:\pythonProject3\交换机端口管理工具

# 默认全量（用默认清单与默认输出）
& "d:\pythonProject3\venv\Scripts\python.exe" network_port_manager.py

# 并发 8 台（现场建议 4~8）
& "d:\pythonProject3\venv\Scripts\python.exe" network_port_manager.py -c 8

# 关闭“发现未知交换机”（更快）
& "d:\pythonProject3\venv\Scripts\python.exe" network_port_manager.py --no-discover

# 只输出部分模块
& "d:\pythonProject3\venv\Scripts\python.exe" network_port_manager.py --sections name links usage

# 指定输入输出
& "d:\pythonProject3\venv\Scripts\python.exe" network_port_manager.py --switch-file a.xlsx --terminal-file b.xlsx --out c.xlsx
```

| 参数 | 说明 |
| --- | --- |
| `--switch-file` | 交换机清单路径，默认 `switch_table.xlsx` |
| `--terminal-file` | 终端 IP 表路径，默认 `终端IP表.xlsx` |
| `--out` | 输出 Excel 路径，默认 `交换机端口资源管理表.xlsx` |
| `-c, --concurrency` | 采集并发度，默认 6 |
| `--no-discover` | 关闭自动发现未知交换机 |
| `--sections` | 可选值：`name links terminal usage suspicious` |

## 5. 输出文件（交换机端口资源管理表.xlsx）

| Sheet | 内容 |
| --- | --- |
| 命名验证 | 期望设备名 vs 实际 sysname，登录失败/名称不一致会标出 |
| 交换机连线 | 由 LLDP 推导的设备互联关系（含端口） |
| 终端接入-分析统计 | 过滤前后数量、异常分类计数 |
| 终端接入表 | **接入口 ↔ 终端一一对应**（已剔除聚合口/虚拟口/核心直连等异常行） |
| 终端接入-异常明细 | 每条例外行的 异常类型 / 原因 / 处理建议 |
| 可疑端口清单 | 物理口 UP + 非级联 + 学到 MAC / 描述像终端 的端口，附判定依据与建议 |
| 端口使用表 / 端口使用表-打印 | 接入交换机逐端口使用情况（级联/终端/聚合/Trunk/Hybrid/空闲） |
| 核心端口使用表 / 核心端口使用表-打印 | 核心交换机逐端口使用情况 |

### “端口使用情况”取值含义
| 取值 | 含义 |
| --- | --- |
| 级联 | 该口有 LLDP 邻居或已知连线，是交换机互联口 |
| 终端 | 该口定位到了终端（含“核心 ARP 无记录但学到 MAC”的可疑终端） |
| 聚合 | 该口属于链路聚合组 |
| Trunk / Hybrid | 按接口类型标记 |
| 空闲 / DOWN 等 | 端口未 UP，或直接展示链路状态原文 |

## 7. 并发与提速说明

本版相对旧版的主要提速点：

1. **一台设备只登录一次**（旧版同台设备会被登录 4 次以上）。
2. **终端定位零额外 SSH**：旧版每台终端都要新建连接并跑多条命令，现改为内存反查。
3. **ARP 采集从 68 条命令降到 1~2 条**。
4. **去掉重复采集**：旧版“扫额外 UP 端口”与“端口使用采集”各跑一遍。
5. **删除无效等待**：`screen-length disable` 只在登录后下发一次。
6. **并发采集**：默认 6 线程，可用 `-c` 调整。

## 8. 常见问题

**Q：提示“已有任务在运行”？**
Web 界面同一时间只允许一个任务，等它结束后再提交。

**Q：提示默认清单不存在？**
把 `switch_table.xlsx` 放到本目录，或在页面上上传后指定路径。

**Q：需要“自动发现未知交换机”但提示没有可用凭据？**
该功能默认使用清单里的账号密码组合。若要用额外兜底账号，启动前设置环境变量：
```powershell
$env:NET_PORT_FALLBACK_CREDS = "admin:你的密码,admin2:另一个密码"
```

**Q：某个终端 VLAN 显示不对？**
VLAN 取值优先级为「MAC 表 VLAN → interface brief 的 PVID」，不再额外登录设备查端口配置（这是提速的一部分）。如需回退为“按需查询端口配置”，告知即可加回。

**Q：网络中断/设备不可达会影响整批吗？**
不会。单台失败只会在“命名验证”里记为登录失败，其余设备继续采集，报告照常生成。
