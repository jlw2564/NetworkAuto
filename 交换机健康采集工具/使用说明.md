## 一、功能总览

本脚本通过 SSH 批量登录华三 (H3C) Comware V7 系列交换机（含盒式接入与框式核心），一次性输出：

1. **交换机配置文件**（每台设备 1 个 .txt）
2. **交换机设备台账.xlsx**（含 型号 / 序列号 SN / 硬件版本 / 软件版本 / 板卡清单）
3. **交换机健康状态总表.xlsx**（3 个 Sheet：设备健康概览 / 端口带宽与光功率 / 异常汇总）
4. **网络拓扑图.html**（基于 LLDP 邻居自动绘制，浏览器直接打开即可查看）

全程无需安装图形化 SSH 工具，**只需要填好 1 份 Excel 清单**，一键运行即可出结果。

### 5.2 交换机健康状态总表.xlsx

共 3 个 Sheet：

#### Sheet 1：设备健康概览

每行一台设备，涵盖：

- **CPU 利用率% / 状态**：60% 告警、80% 错误（可在脚本顶部 `CPU_WARN, CPU_ERR` 调）
- **内存利用率% / 状态**：60% / 85%；框式按多 Slot 取最大值，**优先使用 display memory 表尾 FreeRatio 反算**，避免不同 Comware 版本口径不一致
- **温度（最高传感器）/ 状态 / 温度告警阈值 / 温度错误阈值**：  
  ⚠️ 不使用固定 55/70℃，而是取当前设备 `display environment` 表的 `Warning` 列最小值 × 0.92 作为告警、`Alarm` 列最小值 × 0.95 作为错误  
  ⇒ 现场 S5048PV6 Warning=112 → 告警≈103；核心 inflow Warning=78 → 告警≈72，避免"接入 62℃ 就告警、核心 80℃ 才正常"的双标问题
- **UP端口数 / 总物理端口数 / 带宽采集方法**：显示该机型实际走的是哪条 fallback 链

#### Sheet 2：端口带宽与光功率

每行一个物理端口（包含 BAGG / XGE / GE 等所有 bridge 模式接口），共 24 列，关键字段：

| 字段 | 说明 |
|---|---|
| 速率配置 / 双工 / 接口类型 / PVID / 描述 | 来自 `display interface brief bridge 模式` 段，按表头偏移切列，不会因描述带空格错位 |
| 入 / 出带宽利用率% | **三层 fallback 链（优先级从高到低）**：<br>① `display interface` 的 `Last 300 seconds input/output xx%`（官方 5 分钟口径，S5048PV6 实测有 12% 这种精确值）<br>② `display counters rate inbound outbound interface`（原生 rate 命令机型，如 S7500XG / S5570S）<br>③ `display counters inbound/outbound interface` 两次采样 × `estimate_utilization_from_counters`（默认 30s 间隔 × MTU1500+24 字节 IFG） |
| 带宽状态 | 60% 告警、85% 错误（`BANDWIDTH_WARN/ERR` 可调） |
| 收光 / 发光(dBm) + 收光状态 / 发光状态 | RX 正常 [-18, +3]dBm；TX 正常 [-9, +3]dBm（`RX_PWR_MIN/MAX`、`TX_PWR_MIN/MAX` 可调）；-36.96 这种明显断纤的直接标红"错误" |
| 光模块温度 / 电压 / 电流 | 来自 `display transceiver diagnosis interface`，表头格式已兼容 3 种不同 Comware 子版本 |
| 入 / 出方向错误包 | 数字 0 或具体错包数，来自 counters 命令 Err 列 |
| 入 / 出方向计数溢出 | 当 Err 列显示文字 **Overflow** 时标"是"，并计入异常汇总 |
| 异常标记 | 上述任一异常拼接成文字，如"收光错误;带宽告警;出方向计数溢出" |

#### Sheet 3：异常汇总

按 **错误 / 告警** 分底色（粉 = 错误、浅黄 = 告警），汇总包含：

- 设备级：CPU / 内存 / 温度 / 登录失败
- 端口级：带宽 ≥60% / 收光越界 / 发光越界 / 错包>0 / **计数器 Overflow** / 光模块不支持数字诊断或未插入（若该口应插光模块）

### 5.3 网络拓扑图.html

基于 LLDP 邻居列表（`display lldp neighbor-information list`）自动生成 vis.js 交互式拓扑：

- **节点颜色**：绿色=全部正常；黄色=有告警；红色=有错误/登录失败；灰色核心节点外框加粗

- **连线悬停**：两端对端设备名 + 端口名 + 光模块 RX/TX / 带宽%

## 六、适配的交换机型号与命令集分层 fallback

脚本已经在以下现场型号 **实测样本全通过**：

| 型号 | 典型设备 | 软件版本 | 命令集适配点 |
|---|---|---|---|
| H3C S7503X-M-G（框式核心） | EBG-ELV-ROOM-J01-SA-SWITCH-01 | V7.1.070 R7755P01 | 多 Slot CPU/内存聚合；Chassis self SN；LLDP 端口名长名归一；Warning 列=78/100 双阈值 |
| H3C S5048PV6-EI-PWR（POE 接入） | EBG-1FJ01-SA-SWITCH-02 | V7.1.070 R3507P28 | 无 counters rate → 30s 采样；无 display temperature → 用 display environment；device manuinfo 内才带 SN |
| **H3C S5570S-36F-EI** | （待批量） | V7 R77xx 系推测 | 属 V7 高端接入，原生支持 counters rate + display interface 300s，脚本 ①② 两条 fallback 链直接命中 |

带宽 util 算法 fallback 链（**优先级从高→低**，依次尝试直到命中）：

1. `display counters rate inbound outbound interface` → 若 `% Unrecognized command` → 重试 `display counters rate`
2. `display counters inbound interface` → 等 30s → `display counters inbound/outbound interface` 第 2 次，按报文数差 × (MTU1500+24) ÷ 配置带宽 估算
3. `display interface` 对所有接口抓 `Last 300 seconds input/output xx%` → **覆盖第 1/2 步结果**，作为最终显示值（官方 5 分钟平均口径，最准确）

> 如果现场出现"带宽利用率比实际明显偏大/偏小"，常见原因是第 2 步估计平均包长不准，调整脚本顶部 `estimate_utilization_from_counters` 调用处的 `counter_sample_seconds` 或 `mtu_guess` 即可（但由于第 3 步官方 300s 口径覆盖，一般不需要改）。

## 七、阈值调整位置（在脚本顶部 [L33-L38](file:///d:/pythonProject3/交换机健康采集工具/h3c_switch_health_topology.py#L33-L38)）


## 八、常见问题排查（FAQ）

### Q1. 某台设备登录失败，怎么办？

1. 先在 `交换机设备台账.xlsx` 备注列看异常栈，常见关键字：
   - `Authentication failed` → 用户名/密码错
   - `TCP connection to device failed` / `NetMikoTimeoutException` → 网络不通 / 22 端口被防火墙挡 / 管理 VLAN ACL 拒绝
   - `Unable to find prompt` → 登录后卡在用户视图输入 enable 密码；本脚本默认用户视图权限即可，不需要 super 密码
2. 手 CRT/Xshell 登进后确认：
   - `ssh server enable` 已开
   - `line vty 0 4` 下 `protocol inbound ssh`、`authentication-mode scheme`
   - `local-user admin` 下 `service-type ssh terminal`、`authorization-attribute user-role network-admin`

### Q2. 某台设备 SN=未知 / 型号=未知？

通常是因为该设备 `display device manuinfo` 返回格式不在我们现在支持的 3 种（Chassis self / Slot N CPU N / 直接 key:value）里。直接把该台的 `display device manuinfo` 完整输出贴到对话里，我再补对应 parse 分支即可。

### Q3. 端口的收光 RX/TX 全空？

1. 确认该口真的是光口（不是电口 1000_BASE_T）
2. 手跑 `display transceiver diagnosis interface GE1/0/49`，如果输出是 `The transceiver is absent.` / `does not support this function.` 脚本会把状态写进 Sheet 2 "异常标记" 列，但不会伪造 RX/TX 数值
3. 若手跑有 RX/TX 数值但脚本里为空，把对应口的 display transceiver 输出贴给我，补 parse_transceiver 正则分支

### Q4. 带宽利用率显示 0% 明显不对？

1. 看 Sheet 2 的 "带宽方法_入/出" 是否是 `display_interface_300s`：
   - 如果是 0，说明官方 300s 平均就是 0，真实就是空闲
   - 如果没显示这条，检查 Sheet 1 设备级 "带宽采集方法"：
     - 写 `counters_rate` → 但 counters_rate 本口没值 / 口名匹配失败（长口名/短口名没归一）→ 贴 `display counters rate inbound outbound interface` 的前 20 行
     - 写 `counters_in_out_sample_30s` → 说明 ①③ 两条 fallback 链都没命中，走的是两次采样，改 `counter_sample_seconds` 从 30 调到 60 再跑一次试试

### Q5. 拓扑图里缺某条级联链路？

1. 先查 `交换机设备台账.xlsx` 两端设备"登录状态"是否都成功
2. 两端手跑 `display lldp neighbor-information list`，确认都能互相看到
3. 常见 2 种显示为"非管理邻居"的情况（不会进拓扑节点，但数据完整存在日志里）：
   - System Name = `-`（PC/哑终端/摄像头网卡）
   - Port ID = MAC 地址 xxxx-xxxx-xxxx 而非接口名
